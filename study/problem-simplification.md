# 문제를 간결하게 만드는 법

코딩 테스트 문제의 긴 설명을 그대로 기억하지 않습니다. 문제마다 다른 이름과 상황을 걷어내고, 다음 한 문장으로 바꿉니다.

> **주어진 제약 안에서, 어떤 상태를 어떤 규칙으로 바꾸어 무엇을 구하는가?**

## 1. 문제를 네 줄로 압축한다

코드를 쓰기 전에 아래 네 줄만 채웁니다.

```text
목표: 무엇을 최소화·최대화·판정·계수하는가?
상태: 답을 결정하는 데 필요한 최소 정보는 무엇인가?
행동: 한 단계에서 무엇을 선택하거나 이동하는가?
제약: 입력 크기가 허용하는 시간 복잡도는 무엇인가?
```

예를 들어 “도시에서 도로를 따라 K번 이동해 도착할 수 있는 도시”는 다음처럼 줄어듭니다.

```text
목표: 시작점에서 거리가 K인 정점 찾기
상태: 정점별 시작점으로부터의 최단 거리
행동: 현재 정점에서 인접 정점으로 이동
제약: 모든 간선 비용이 1이므로 BFS 한 번, O(V + E)
```

## 2. 문제의 장식을 지운다

| 문제 속 표현 | 남겨야 할 구조 |
|---|---|
| 사람, 상품, 포켓몬, 노래 | 값 또는 객체 |
| 도시, 컴퓨터, 친구 관계 | 정점과 간선 |
| 상하좌우 이동, 미로, 지도 | 격자 그래프 |
| 연속한 날짜, 구간, 부분 배열 | 연속 구간 |
| 고르기, 배치하기, 모든 경우 | 선택 트리 |
| 매 순간 가장 좋은 선택 | 그리디 후보 |
| 이전 결과를 재사용 | DP 후보 |

고유명사를 `값`, `인덱스`, `정점`, `간선`, `구간`, `상태`로 바꾸어 말할 수 있으면 문제가 단순해집니다.

## 3. 먼저 완전탐색을 만든다

최적 풀이를 바로 떠올리려 하지 말고 가장 단순한 정답부터 정의합니다.

1. 가능한 답을 어떻게 모두 만들 수 있는가?
2. 경우의 수는 몇 개인가?
3. 중복 계산되는 정보는 무엇인가?
4. 정렬, 해시, 누적합, 가지치기, 메모이제이션으로 무엇을 줄일 수 있는가?

최적화는 대부분 아래 중 하나입니다.

- **탐색 횟수 줄이기:** 해시, 이분 탐색, 투 포인터
- **같은 계산 재사용:** 누적합, DP, 방문 배열
- **불필요한 후보 제거:** 정렬, 그리디, 가지치기
- **상태를 작게 유지:** 슬라이딩 윈도우, 힙, 단조 스택
- **문제를 그래프로 보기:** BFS, DFS, 다익스트라, 위상 정렬

## 4. 입력 크기로 후보를 제거한다

정확한 기준은 언어와 연산에 따라 달라지지만, 후보를 압축하는 초기 기준으로 사용합니다.

| 입력 크기 `N` | 먼저 검토할 복잡도 |
|---:|---|
| `N <= 20` | `O(2^N)`, 백트래킹, 비트마스크 |
| `N <= 100` | `O(N^3)` 가능성 검토 |
| `N <= 2,000` | `O(N^2)` 가능성 검토 |
| `N <= 100,000` | `O(N log N)`, `O(N)` |
| `N >= 1,000,000` | 작은 상수의 `O(N)` 중심 |

숫자를 외우는 목적은 정답 알고리즘을 맞히는 것이 아니라, 불가능한 후보를 빨리 버리는 것입니다.

## 5. 단서가 아니라 조건으로 알고리즘을 선택한다

표면적인 키워드 하나만 보고 유형을 결정하지 않습니다.

| 확인할 조건 | 후보 |
|---|---|
| 존재 여부·빈도·그룹이 필요한가? | `set`, `dict`, `Counter` |
| 연속 구간이고 경계를 움직일 수 있는가? | 투 포인터, 슬라이딩 윈도우 |
| 구간 합을 반복해서 묻는가? | 누적합 |
| 정렬 후 앞선 선택이 뒤의 선택을 단순화하는가? | 그리디 |
| 답의 범위에서 “가능/불가능”이 단조로운가? | 이분 탐색 |
| 가중치 없는 최단 이동인가? | BFS |
| 연결된 모든 곳 탐색·경우의 수 탐색인가? | DFS/BFS |
| 음수가 없는 가중치 최단 거리인가? | 다익스트라 |
| 선행 관계가 있는가? | 위상 정렬 |
| 같은 입력 상태의 답을 반복 계산하는가? | DP/메모이제이션 |
| 가장 작은·큰 후보를 계속 꺼내는가? | 힙 |

## 6. 구현 전에 불변식을 한 문장으로 쓴다

불변식은 “반복문의 각 시점에 항상 참인 것”입니다. 코드의 조건문을 결정하고 디버깅 기준이 됩니다.

- BFS: 큐에서 꺼낸 정점의 거리는 이미 가능한 최단 거리다.
- 투 포인터: 현재 구간은 지금까지 정한 유효성 조건을 만족한다.
- 다익스트라: 힙에서 꺼낸 거리보다 더 짧은 기록이 있으면 그 항목은 폐기한다.
- DP: `dp[i]`에는 `i`까지의 문제에 대한 정의된 최적값이 저장된다.

불변식을 말할 수 없다면 아직 구현을 시작할 단계가 아닙니다.

## 7. 실전에서는 10분 안에 결정한다

```text
0~3분   목표·입력·출력을 네 줄로 압축
3~6분   완전탐색 비용과 제거할 중복 계산 확인
6~8분   후보 알고리즘 1~2개와 불변식 작성
8~10분  복잡도·반례 확인 후 구현 또는 보류 결정
```

10분 후에도 핵심 상태와 복잡도를 설명할 수 없다면, 모의고사에서는 보류 후보입니다. 학습 중이라면 정답 대신 “내가 잘못 고정한 가정 하나”에 대한 힌트만 받습니다.

## 8. 풀이 후에는 코드가 아니라 변환을 기록한다

다음 세 문장만 남겨도 같은 유형을 다시 알아보기 쉬워집니다.

```text
이 문제의 장식을 지우면: ____________________ 문제다.
완전탐색에서 줄인 것은: ____________________ 이다.
다음에는 ____________________ 조건을 보면 이 정석을 후보로 올린다.
```
