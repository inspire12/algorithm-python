# 지금까지 다룬 알고리즘 유형 요약

이 문서의 문제별 상태는 `study/problem-registry.json`만을 기준으로 작성합니다. 유형 설명은 강의용 재사용 지식이며, 이해도와 다음 복습 행동은 레지스트리를 기준으로 판단합니다.

## 상태 읽는 법

- `B`: 아이디어와 구현 경험은 있으나 독립 설명 또는 간격 복습이 남음
- `C`: 정답 또는 핵심 구현을 확인했으므로 무참조 재구현이 필요함
- `U`: 완료 근거가 없거나 아직 학습 중임

현재 레지스트리에는 이해도 `A`로 검증된 문제가 없습니다. 강의 자료를 읽고 설명할 수 있는 것과 기존 코드 없이 구현할 수 있는 것을 구분해야 합니다.

## 1. 해시 조회

### 인식 단서

- 이전에 본 값의 존재, 빈도, 위치를 반복해서 찾는다.
- 기준 풀이에서 매 원소마다 다른 원소를 다시 순회한다.

### 적용 조건

- 필요한 조건을 키로 표현할 수 있다.
- 평균 `O(1)` 조회로 반복 탐색을 바꿀 수 있다.

### 상태와 연산

- 키: 현재 또는 미래에 조회할 조건
- 값: 인덱스, 빈도, 그룹 등 문제에서 반환하거나 갱신할 정보
- 연산: 조회, 삽입, 빈도 증가·감소

### 최소 불변식

> 반복 시작 시 맵에는 현재 인덱스보다 앞에서 확인한 원소의 정보만 있다.

### 대표 문제와 현재 보완점

- Two Sum — `B`
- 보완: 조회 후 삽입이 같은 인덱스 재사용을 막는 이유를 독립적으로 설명

## 2. 읽기·쓰기 포인터

### 인식 단서

- 배열을 제자리에서 수정해야 한다.
- 읽은 원소 중 조건을 만족하는 값만 앞쪽에 압축한다.

### 적용 조건

- 입력 순서를 유지하면서 유효한 접두 구간을 만들 수 있다.
- 반환 계약이 전체 배열이 아니라 유효한 길이 또는 접두 범위다.

### 상태와 연산

- `read_index`: 다음으로 검사할 원소
- `write_index`: 다음 유효 원소를 기록할 위치

### 최소 불변식

> `nums[:write_index]`에는 지금까지 확정된 유효 원소만 문제의 요구 순서대로 저장되어 있다.

### 대표 문제와 현재 보완점

- Remove Duplicates from Sorted Array — `C`
- 보완: 쉬운 문제로 보류했지만 무참조 제자리 구현과 반환 범위 검증이 남음

## 3. 양끝 투 포인터

### 인식 단서

- 정렬된 배열 또는 양끝 경계가 주어진다.
- 한 번의 비교로 한쪽 후보 묶음을 제거할 수 있다.

### 적용 조건

- 포인터 이동 방향에 단조성 또는 후보 제거 증명이 있다.
- 제거한 후보가 이후 정답이 될 수 없음을 설명할 수 있다.

### 상태와 연산

- `left`, `right`: 아직 검사할 후보 범위
- 현재 상태와 누적 정답을 서로 다른 변수로 관리

### 최소 불변식

> 반복 시작 시 정답 후보는 닫힌 구간 `[left, right]` 안에 남아 있고, 구간 밖 후보는 정답이 될 수 없음이 증명되었다.

### 대표 문제와 현재 보완점

- Two Sum II — `B`: 합 비교에 따른 포인터 이동 증명
- Container With Most Water — `B`: 낮은 벽 제거 부등식과 총 이동 횟수 설명
- 3Sum — `B`: 결과 집합 없이 반복 내부에서 중복 제거
- Trapping Rain Water — `C`: 구간 확정 또는 낮은 경계 확정 불변식으로 무참조 구현

## 4. 슬라이딩 윈도우

### 인식 단서

- 정답 후보가 연속 부분 배열 또는 부분 문자열이다.
- 오른쪽을 한 칸 늘릴 때 이전 구간 상태를 재사용할 수 있다.

### 적용 조건

- 창에 원소를 추가하고 제거할 때 합, 빈도, 조건 상태를 증분 갱신할 수 있다.
- 가변 창에서는 왼쪽을 이동해 조건을 복구하는 단조성이 필요하다.

### 상태와 연산

- `left`, `right`: 현재 창
- 창의 합, 값별 빈도, 충족한 조건 개수
- 오른쪽 추가, 조건 위반 시 왼쪽 제거, 현재 답 갱신

### 최소 불변식

> 현재 상태 변수는 정확히 `window[left:right+1]`의 정보와 일치한다.

### 대표 문제와 현재 보완점

- Subarrays with K Different Integers — `B`: `exactly(k) = atMost(k) - atMost(k-1)` 무참조 구현
- Minimum Window Substring — `C`: `required`, `window`, `formed`와 제거 시점 갱신
- Maximum Average Subarray I, Permutation in String — `U`: 고정 창 완료 여부 검증 필요
- Longest Substring Without Repeating Characters, Minimum Size Subarray Sum, Fruit Into Baskets, Max Consecutive Ones III, Longest Repeating Character Replacement — `U`: 과거 기록은 있으나 독립 완료 근거 없음

## 5. 일반 스택과 단조 스택

### 인식 단서

- 가장 최근의 미해결 항목부터 처리한다.
- 현재 값이 이전 후보 여러 개의 답을 한꺼번에 확정한다.

### 적용 조건

- 후보 해결 순서가 LIFO 구조와 맞아야 한다.
- 단조 스택에서는 새 값에 의해 지배되는 스택 위 후보를 안전하게 제거할 수 있어야 한다.

### 상태와 연산

- 스택에는 값보다 인덱스를 저장해 값 조회와 거리 계산을 함께 지원
- 현재 값과 `nums[stack[-1]]` 비교
- 해결된 후보를 `pop`하고 결과 기록

### 최소 불변식

> 스택에는 아직 답이 확정되지 않은 인덱스만 있고, 대응 값은 문제에 필요한 단조 순서를 유지한다.

### 대표 문제와 현재 보완점

- Valid Parentheses — `U`: 독립 완료 여부 검증 필요
- Daily Temperatures — `C`: 엄격한 비교, 중첩 인덱스 조회, 상환 `O(n)` 설명
- Largest Rectangle in Histogram — `C`: 막대의 좌우 경계, `right-left-1`, 종료 센티널
- Remove K Digits — `U`: 탐욕적 제거 증명, 남은 제거, 앞자리 0 처리

## 6. 단조 큐

### 인식 단서

- 이동하는 구간에서 최댓값 또는 최솟값을 반복해서 요구한다.
- 오래된 후보의 만료와 새 값에 지배되는 후보 제거가 동시에 필요하다.

### 적용 조건

- 덱 앞에서는 윈도우 범위를 벗어난 후보를 판별할 수 있다.
- 덱 뒤에서는 현재 값보다 불리하고 더 먼저 만료될 후보를 제거할 수 있다.

### 상태와 연산

- 덱에는 후보의 인덱스를 저장
- 앞: 인덱스 만료 검사와 `popleft`
- 뒤: 값의 지배 관계 검사와 `pop`

### 최소 불변식

> 덱에는 현재 창에서 아직 답이 될 수 있는 인덱스만 있고, 대응 값은 앞에서 뒤로 문제에 필요한 단조 순서를 이룬다.

### 대표 문제와 현재 보완점

- Sliding Window Maximum — `B`: 두 제거 조건의 무참조 구현과 각 인덱스가 한 번 들어가고 나오는 `O(n)` 설명
- Longest Continuous Subarray With Absolute Diff Less Than or Equal to Limit — `B`: 최대·최소 덱의 두 불변식과 왼쪽 복구 조건

## 7. 이분 탐색

### 인식 단서

- 정렬된 값에서 대상을 찾는다.
- 후보에 대한 가능·불가능 판정이 단조롭다.

### 적용 조건

- 비교 결과로 후보 범위의 절반을 안전하게 제거할 수 있다.
- 열린 구간 또는 닫힌 구간 계약을 반복 전체에서 유지할 수 있다.

### 상태와 연산

- `search_left`, `search_right`, `middle`
- 현재 후보 검사와 절반 제거

### 최소 불변식

> 반복 시작 시 정답이 존재한다면 현재 탐색 구간 안에 있다.

### 대표 문제와 현재 보완점

- Binary Search — `B`: 간격을 둔 무참조 재구현
- Find First and Last Position of Element in Sorted Array — `U`: lower/upper bound 반환 계약

## 8. 특수 유형: 두 정렬 배열의 파티션 이분 탐색

### 인식 단서

- 두 배열이 각각 정렬되어 있다.
- 합친 순서의 중앙값 또는 `k`번째 원소가 필요하다.
- 실제 병합보다 빠른 복잡도를 요구한다.

### 상태와 연산

- 짧은 배열의 왼쪽 원소 개수만 이분 탐색
- 긴 배열의 왼쪽 원소 개수는 전체 필요 개수에서 빼서 계산
- 네 경계값과 두 교차 조건 검사

### 최소 불변식

> 전체 왼쪽 원소 수는 항상 필요한 순위 개수이고, 탐색 구간에는 두 교차 조건을 만족할 수 있는 짧은 배열의 파티션 후보만 남아 있다.

### 대표 문제와 현재 보완점

- Median of Two Sorted Arrays — `C`
- 보완: 무참조 구현, 짧은 배열 탐색의 유효 범위 증명, 센티널과 홀짝 반환
- 상세 카드: [특수 문제 유형](special-problem-types.md#두-정렬-배열의-파티션-이분-탐색)

## 유형을 고를 때 공통으로 묻는 질문

1. 정답 후보 하나는 정확히 무엇인가?
2. 모든 후보를 검사하는 기준 풀이의 복잡도는 무엇인가?
3. 가장 많이 반복되는 연산 하나는 무엇인가?
4. 어떤 상태를 저장하면 그 반복을 제거할 수 있는가?
5. 이번 비교로 제거하는 후보는 무엇인가?
6. 제거한 후보가 정답일 수 없는 이유는 무엇인가?
7. 현재 상태와 누적 정답이 서로 다른 변수로 분리되어 있는가?
8. 각 원소나 후보가 자료구조에 들어가고 나오는 총횟수는 몇 번인가?

## 현재 공통 보완 과제

레지스트리의 여러 문제에서 반복되는 보완점은 다음과 같습니다.

- 정답 코드를 확인한 뒤 기존 코드 없이 다시 구현하기
- 포인터 이동과 후보 제거를 직관이 아니라 부등식으로 설명하기
- 덱과 스택의 중첩 `while`을 원소별 총 진입·제거 횟수로 분석하기
- 값과 인덱스, 현재 상태와 누적 정답을 분리하기
- 유형 이름보다 적용 조건과 필요한 연산을 먼저 말하기
