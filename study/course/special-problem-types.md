# 특수 문제 유형

기본 알고리즘만으로 이름을 붙이기 어려우며, 여러 조건이 함께 나타날 때 사용하는 특수 유형을 정리합니다. 유형 이름만 암기하지 않고 인식 단서와 적용 조건을 모두 확인합니다.

## 두 정렬 배열의 파티션 이분 탐색

- 대표 문제: [Median of Two Sorted Arrays](https://leetcode.com/problems/median-of-two-sorted-arrays/)
- 상세 강의: [두 정렬 배열의 파티션 이분 탐색](concepts/binary-search-partition.md)

### 인식 단서

- 두 배열이 각각 정렬되어 있다.
- 두 배열을 합친 순서에서 중앙값 또는 `k`번째 값을 요구한다.
- 실제 병합의 `O(m+n)`보다 빠른 복잡도를 요구한다.
- 한 배열에서 선택한 원소 수가 정해지면 다른 배열에서 선택할 원소 수가 자동으로 정해진다.

### 적용 조건

- 두 배열이 비내림차순으로 정렬되어 있어야 한다.
- 전체 순위의 경계만 필요하고 실제 병합 결과는 필요하지 않아야 한다.
- 파티션 위치가 움직일 때 네 경계값이 단조롭게 변해야 한다.

### 적용하지 않는 조건

- 입력 배열이 정렬되어 있지 않다.
- 합친 배열 전체를 출력해야 한다.
- 순위가 아니라 원소별 대응 관계나 원래 순서가 필요하다.
- `O(m+n)` 병합으로 충분하고 더 단순한 풀이가 요구사항을 만족한다.

### 필요한 상태와 연산

```text
nums1_left_count   # 이분 탐색하는 파티션 개수
nums2_left_count   # 필요한 전체 왼쪽 개수에서 자동 계산

nums1_left_max
nums1_right_min
nums2_left_max
nums2_right_min
```

필요한 연산은 파티션 개수 선택, 네 경계 조회, 두 교차 조건 비교입니다. 각 후보 검사는 `O(1)`입니다.

### 최소 불변식

> 전체 왼쪽 원소 수는 항상 필요한 순위 개수로 고정되고, 탐색 구간에는 두 교차 조건을 만족할 수 있는 짧은 배열의 파티션 후보만 남아 있다.

### 최소 판단 템플릿

```text
1. 짧은 배열에서 왼쪽에 넣을 원소 개수를 탐색한다.
2. 다른 배열의 왼쪽 원소 개수는 전체 필요 개수에서 빼서 정한다.
3. 두 배열의 교차 경계를 검사한다.
4. 첫 번째 배열의 왼쪽 경계가 너무 크면 파티션 개수를 줄인다.
5. 두 번째 배열의 왼쪽 경계가 너무 크면 첫 번째 배열의 파티션 개수를 늘린다.
```

### 대표 변형

- 두 정렬 배열의 중앙값
- 두 정렬 배열을 합쳤을 때의 `k`번째 원소
- 전체 왼쪽에 정확히 `k`개를 배치하는 순위 경계 탐색

### 대표 실수

- 두 배열의 중앙 인덱스를 각각 독립적으로 탐색한다.
- 파티션 개수가 아니라 값 자체를 탐색한다.
- 전체 왼쪽 원소 수를 고정하지 않는다.
- 같은 배열 내부만 비교하고 두 교차 조건을 누락한다.
- 긴 배열을 탐색해 다른 배열의 파티션 인덱스가 범위를 벗어난다.

## 머리 풀기: 경계 확정형 단조 스택

- 대표 문제: [Largest Rectangle in Histogram](https://leetcode.com/problems/largest-rectangle-in-histogram/)
- 머리 풀기 목록: [전용 문제 목록](warm-up-problems.md#largest-rectangle-in-histogram)
- 용도: 단조 스택의 `pop` 시점과 포함·제외 경계를 짧게 복구하는 워밍업

### 인식 단서

- 각 원소를 최솟값 또는 기준 높이로 고정한 연속 구간이 후보가 된다.
- 후보의 최대 범위는 왼쪽과 오른쪽에서 처음 만나는 더 낮은 값으로 결정된다.
- 기준 풀이가 각 원소마다 양쪽 경계를 다시 탐색해 `O(N²)`이 된다.

### 필요한 상태와 연산

```text
increasing_indices:
오른쪽의 더 낮은 막대를 아직 만나지 않아
최대 너비가 확정되지 않은 막대 인덱스
```

```text
현재 높이가 스택 위 높이보다 낮음
→ 높은 막대를 pop
→ 해당 막대의 포함 양끝과 넓이 확정
```

### 포함 경계 공식

막대를 `pop`한 직후:

```python
rectangle_left = (
    increasing_indices[-1] + 1
    if increasing_indices
    else 0
)
rectangle_right = current_index - 1
width = rectangle_right - rectangle_left + 1
```

현재 위치는 pop된 막대보다 낮아서 포함할 수 없고, pop 후 스택 위 위치도 왼쪽 확장을 막으므로 둘의 안쪽만 포함합니다.

### 최소 불변식

> 스택에는 오른쪽의 더 낮은 경계를 아직 만나지 않은 인덱스가 높이 비감소 순서로 있고, pop된 막대의 최대 직사각형은 모두 계산되었다.

### 센티널

끝까지 비감소하는 입력에서는 막대가 스택에 남습니다. 높이 `0`의 가상 막대를 끝에 추가해 모든 남은 막대의 포함 오른쪽 경계를 배열 끝으로 확정합니다.

```python
heights_with_end_marker = heights + [0]
```

### 암기할 것

- 스택에는 값이 아니라 인덱스를 저장한다.
- 현재 높이가 더 낮을 때만 높은 막대를 `pop`한다.
- 포함 왼쪽은 `pop` 후 스택 위의 다음 칸이다.
- 포함 오른쪽은 현재 위치의 이전 칸이다.
- 끝에 높이 `0` 센티널을 둔다.

### 이해할 것

- 현재 위치가 pop된 막대의 첫 오른쪽 낮은 경계인 이유
- pop 이후 스택 위가 가장 가까운 왼쪽 방해 경계인 이유
- 각 인덱스가 한 번 들어가고 최대 한 번 나와 전체가 `O(N)`인 이유

### 머리 풀기 확인 질문

1. `pop`되는 막대의 포함 양끝은 어디인가?
2. 너비를 `right-left+1`로 쓸 때 `left`, `right`는 무엇을 포함하는가?
3. `[2, 1, 2]`에서 높이 `1`의 너비는 언제 `3`으로 확정되는가?
4. 센티널이 없으면 `[1, 2, 3]`에서 어떤 막대들이 미확정으로 남는가?
