# 두 정렬 배열의 파티션 이분 탐색

## 학습 목표

- 두 정렬 배열을 병합하지 않고 전체 중앙 경계를 찾는다.
- 파티션 개수를 정답 후보로 정의한다.
- 교차 경계 비교로 탐색 방향을 증명한다.
- 경계 밖 값을 센티널로 처리한다.

## 1. 인식 단서

- 두 배열이 각각 정렬되어 있다.
- 두 배열을 합쳤을 때의 특정 순위 값을 요구한다.
- 실제 병합의 `O(m+n)`보다 빠른 복잡도를 요구한다.
- 한 배열에서 선택하는 왼쪽 원소 수가 변할 때 경계값이 단조롭게 변한다.

## 2. 적용 조건

- 두 배열은 각각 비내림차순으로 정렬되어 있어야 한다.
- 두 배열을 합친 순서에서 중앙값 또는 특정 순위의 경계가 필요해야 한다.
- 빈 배열 경계를 일관되게 처리할 수 있어야 한다.

정렬되지 않은 배열이나 전체 병합 결과 자체가 필요한 문제에는 이 방식을 바로 적용할 수 없습니다.

## 3. 문제 계약

길이가 `m`, `n`인 두 정렬 배열에서 전체 중앙값을 구합니다. 실제 병합은 하지 않습니다. 전체 왼쪽 파티션은 다음 개수의 원소를 가져야 합니다.

```python
left_total_count = (m + n + 1) // 2
```

- 전체 길이가 짝수면 왼쪽과 오른쪽의 개수가 같습니다.
- 전체 길이가 홀수면 중앙값을 포함하는 왼쪽이 하나 더 많습니다.

## 4. 정답 후보와 기준 풀이

더 짧은 배열을 `nums1`이라고 할 때 후보는 다음과 같습니다.

```text
nums1_left_count = 0, 1, 2, ..., m
```

후보 하나를 선택하면 다른 배열의 왼쪽 원소 수는 자동으로 정해집니다.

```python
nums2_left_count = left_total_count - nums1_left_count
```

기준 풀이는 모든 `nums1_left_count`를 차례로 검사합니다. 이 경우 후보 검사에 `O(m)`이 걸립니다.

## 5. 파티션 유효 조건

네 경계를 정의합니다.

```text
nums1_left_max   | nums1_right_min
nums2_left_max   | nums2_right_min
```

각 배열 내부의 정렬 관계는 이미 성립합니다. 따라서 두 교차 조건만 검사합니다.

```text
nums1_left_max <= nums2_right_min
nums2_left_max <= nums1_right_min
```

두 조건을 모두 만족하면 전체 왼쪽의 모든 값이 전체 오른쪽의 모든 값 이하입니다.

## 6. 후보 제거와 탐색 방향

```text
nums1_left_max > nums2_right_min
```

이면 `nums1`의 왼쪽에 너무 큰 값이 들어왔습니다. `nums1_left_count`를 줄여야 합니다. 더 큰 후보에서는 `nums1_left_max`가 작아지지 않으므로 현재 후보 이상의 범위를 제거할 수 있습니다.

반대로:

```text
nums2_left_max > nums1_right_min
```

이면 `nums1`의 왼쪽 원소 수가 너무 적습니다. `nums1_left_count`를 늘려야 합니다.

## 7. 경계 센티널

파티션이 배열의 처음이나 끝에 있을 수 있습니다.

```python
nums1_left_max = float("-inf") if nums1_left_count == 0 else nums1[nums1_left_count - 1]
nums1_right_min = float("inf") if nums1_left_count == m else nums1[nums1_left_count]
```

`nums2`에도 같은 규칙을 적용합니다. 빈 왼쪽은 최댓값 비교에 영향을 주지 않도록 `-inf`, 빈 오른쪽은 최솟값 비교에 영향을 주지 않도록 `inf`를 사용합니다.

## 8. 중앙값 추출

올바른 파티션을 찾은 뒤:

```python
left_max = max(nums1_left_max, nums2_left_max)
```

전체 길이가 홀수면 `left_max`가 중앙값입니다. 짝수라면:

```python
right_min = min(nums1_right_min, nums2_right_min)
median = (left_max + right_min) / 2
```

## 9. 불변식

> 전체 왼쪽 원소 수는 항상 `(m+n+1)//2`이고, 탐색 구간에는 두 교차 조건을 만족할 수 있는 `nums1_left_count` 후보만 남아 있다.

짧은 배열을 탐색하면 후보가 `0`부터 `min(m,n)`까지이므로 시간 복잡도는 `O(log(min(m,n)))`입니다. 또한 계산된 `nums2_left_count`가 유효 범위에 머물도록 만들기 쉽습니다.

## 10. 대표 실수

| 잘못된 판단 | 결과 |
|---|---|
| 두 배열의 중앙 인덱스를 각각 독립적으로 탐색 | 전체 왼쪽 원소 수 계약이 깨짐 |
| 값 자체를 탐색 후보로 사용 | 파티션 경계와 중앙 순위를 연결하기 어려움 |
| 같은 배열의 경계만 비교 | 두 배열 사이의 전체 정렬 관계를 보장하지 못함 |
| 빈 파티션을 별도 분기만으로 처리 | 경계 조건이 많아지고 누락되기 쉬움 |
| 긴 배열을 이분 탐색 | 다른 배열의 파티션 인덱스가 범위를 벗어날 수 있음 |

## 11. 최소 템플릿의 순서

1. 더 짧은 배열을 탐색 대상으로 만든다.
2. 전체 왼쪽 원소 수를 계산한다.
3. 짧은 배열의 왼쪽 원소 수를 이분 탐색한다.
4. 긴 배열의 왼쪽 원소 수를 자동 계산한다.
5. 네 경계를 센티널과 함께 구한다.
6. 두 교차 조건을 검사한다.
7. 실패한 조건에 따라 후보 절반을 제거한다.
8. 홀짝에 따라 중앙값을 반환한다.

완성 코드를 암기하기 전에 이 여덟 단계와 탐색 방향의 근거를 말할 수 있어야 합니다.
