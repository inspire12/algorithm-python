# 스터디 운영 가이드

## 기본 운영

- 기간: 12주
- 권장 인원: 4~6명
- 첫 주 시작 전: 120분 진단 테스트
- 매주: 필수 3문제, 선택 2문제, 모의고사 1회, 재풀이

## 매주 문제 구성

문제는 [프로그래머스 코딩테스트 고득점 Kit](https://school.programmers.co.kr/learn/challenges?tab=algorithm_practice_kit)와 [LeetCode Study Plan](https://leetcode.com/studyplan/)을 중심으로 선정합니다.

- 프로그래머스: 국내 채용형 문제 해석과 함수 구현 연습
- LeetCode: 같은 알고리즘의 클래식 패턴과 변형 반복
- 기본 비율: 프로그래머스 3문제, LeetCode 2문제
- 유료 전용 문제는 전원이 접근할 수 있을 때만 선정

### 필수 3문제

1. 프로그래머스의 해당 주차 기본 정석 문제
2. LeetCode의 같은 패턴 변형 문제
3. 프로그래머스의 복합 또는 실전형 문제

### 선택 2문제

- LeetCode의 난도가 높은 변형 문제
- 두 플랫폼 중 해당 주의 부족한 유형을 보완하는 문제

### 주간 모의고사

- 기본 구성은 프로그래머스 2문제와 LeetCode 1문제입니다.

- 90~120분 동안 서로 다른 유형 3문제를 푼니다.
- 검색과 AI를 사용하지 않습니다.
- 정답 수와 함께 문제별 사용 시간, 풀이 순서, 보류 판단을 기록합니다.

## 문제 선정 기준

1. 이번 주의 정석을 자연스럽게 적용하는가?
2. 적용 단서와 불변식을 설명하기 좋은가?
3. 기존 문제와 핵심 아이디어가 지나치게 겹치지 않는가?
4. 필수 문제는 40분 내에 시도할 수 있는 난이도인가?
5. 플랫폼의 표시 난이도보다 스터디의 진단 결과에 맞는가?
6. 정답 코드 대신 문제 링크와 자신의 풀이만 저장하는가?

## 문제 풀이 절차

1. [문제를 간결하게 만드는 법](problem-simplification.md)에 따라 문제를 네 줄로 압축합니다.
2. [문제 분석지](templates/problem-analysis.md)를 코드보다 먼저 작성합니다.
3. [유형별 스니펫 지도](snippet-map.md)에서 후보를 최대 두 개로 줄입니다.
4. 최소 40분 동안 독립적으로 시도합니다.
5. 막히면 정답 대신 잘못된 가정 하나에 대한 힌트만 요청합니다.
6. 풀이를 비교하고 [오답 기록지](templates/retrospective.md)를 작성합니다.
7. 48시간 이내와 7일 후에 AI 없이 재구현합니다.

## 세 가지 성장 지표

매주 푼 문제 수 대신 다음을 기록합니다.

| 지표 | 측정 방법 | 주간 목표 |
|---|---|---|
| 문제 단순화 | 10분 안에 목표·상태·행동·제약 작성 | 필수 문제 전부 |
| 스니펫 숙련 | 검색 없이 최소 코드와 테스트 작성 | 이번 주 핵심 유형 1개 이상 |
| 실전 통과 | 제한 시간 내 정답과 제출 전 검증 | 모의고사 중간 난이도 2문제 이상 |

반복해서 헷갈린 판단과 구현 습관은 [라이브 코딩 오답노트](notes/live-coding-mistakes.md)에 누적합니다. 새 문제를 풀기 전에는 전체 풀이를 다시 읽지 않고 문서 하단의 `문제 풀이 전 30초 체크`만 확인합니다.

## AI 사용 규칙

### 1단계: 독립 풀이

최소 40분 동안 직접 시도합니다.

### 2단계: 힌트만 요청

```text
정답이나 코드를 말하지 말고,
내 접근에서 잘못된 가정 하나만 알려줘.
```

### 3단계: 풀이 비교

- 내가 놓친 문제의 단서는 무엇이었는가?
- 내 접근은 어느 입력 크기까지 가능했는가?
- 정답 풀이는 어떤 상태를 줄였는가?

### 4단계: AI 없이 재구현

설명을 이해한 것이 아니라 혼자 다시 작성했을 때 완료합니다.

## 실패 분류

| 분류 | 판단 기준 |
|---|---|
| 해석 실패 | 조건이나 구해야 할 값을 잘못 이해함 |
| 복잡도 실패 | 입력 크기에 맞지 않는 접근을 시도함 |
| 패턴 인식 실패 | 문제의 단서에서 알고리즘 후보를 떠올리지 못함 |
| 상태 정의 실패 | 필요한 정보를 누락하거나 불필요하게 많이 저장함 |
| 구현 실패 | 인덱스, 방문 처리, 초기화 등에서 실수함 |
| 검증 실패 | 경계값과 반례를 확인하지 않음 |
| 전략 실패 | 한 문제에 시간을 과도하게 사용하거나 순서를 잘못 정함 |


## 개인 학습 지도 연동

프로젝트 루트에서 `python3 study/atlas_server.py --open`을 실행하면 마인드맵 앱과 `study/problem-registry.json`이 연동됩니다. 앱의 자기평가·막힌 지점은 선택된 문제의 `self_assessment`로 학습에 전달됩니다. 실행 방법과 저장·충돌 처리 설명은 [Algorithm Atlas](../sites/algorithm-atlas/README.md)를 참고하세요.
